# Ltx JC RAG 知识库会话任务

## 目标

在桌面端“新会话”入口附近增加“知识库会话”，用户新建后明确看到已经进入知识库会话，并且该会话的回答默认必须通过已选择的知识库内容完成。

## 范围

- 以 `ltx-jc-rag` 插件实现主要能力，名称和 UI 文案继续保留 `Ltx JC RAG` 标识。
- 桌面端只补一个通用 sidebar 扩展插槽，让插件可以把入口放在“新会话”下面。
- 知识库会话采用严格模式：回答必须优先检索挂载知识库；没有相关内容时，应说明知识库未找到，而不是用通用知识补答。
- 会话级挂载默认开启召回并使用 `audit` 审核写入，避免普通问答直接写入正式知识库。
- 管理台入口继续保留在 sidebar footer，兼容旧桌面版本。

## 实现步骤

1. 在桌面 sidebar shell 增加 `sidebar.new-session.action` list slot，owner 提供 `wide` 和 `expandSidebar`。
2. 在插件客户端注册 `知识库会话` quick action，点击后读取可用知识库、选择目标库、创建 session、写入 session mount 并打开会话。
3. 用 mount `extractionInstructions` 保存严格模式标记，使服务端召回、工具文案和系统提示都能识别该会话。
4. 在会话 composer dock 增加可见提示条，展示“已进入 Ltx JC RAG 知识库会话”和当前绑定知识库。
5. 补充桌面 slot 测试和插件运行时/客户端契约测试。
6. 构建、测试、打包、安装插件并重启桌面开发服务。

## 验收

- 展开 sidebar 时，“知识库会话”出现在“新会话”下方。
- 折叠 sidebar 时，该入口显示为可点击图标，点击会先展开再选择知识库。
- 创建成功后自动打开新会话，并显示知识库会话提示条。
- 该会话的系统提示包含严格知识库回答协议。
- `knowledge_base_search` 和 `knowledge_search` 在严格模式无命中时，不再提示继续使用普通知识回答。
- 相关单元测试通过，插件重新打包安装后桌面可启动。
