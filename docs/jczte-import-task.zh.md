# Ltx JC RAG 知识库导入任务

## 目标

为 `ltx-jc-rag` 增加第一版知识导入能力，让用户可以在管理台把本地资料导入到指定知识库。第一阶段优先支持 Markdown、TXT、JSON、JSONL、CSV，导入结果默认进入待审核候选，避免脏数据直接污染正式知识。

## 范围

- 在管理台增加“导入”入口。
- 支持一次选择多个文件。
- 支持选择目标知识库。
- 支持配置导入模式：
  - 生成待审核知识。
  - 直接写入知识库。
- 支持为本次导入追加统一标签。
- 支持选择知识类型：偏好、事实、决策、流程、经验。
- 后端提供同源管理 API，统一完成解析、校验和写入。
- 返回导入摘要：成功数量、失败数量、候选数量、直接写入数量。

## 文件格式

### Markdown / TXT

- 每个文件导入为一个知识草稿。
- 文件名去掉扩展名后作为标题。
- 文件正文作为内容。
- 单个文件最大 15 MiB；超过单条知识正文上限的大文本会按行拆成多篇文档。

### JSON

支持单个对象或对象数组：

```json
{
  "title": "VPN 配置规范",
  "body": "内网访问需要使用指定 VPN。",
  "tags": ["网络", "VPN"],
  "type": "procedure"
}
```

字段兼容：

- `title` 或 `name`
- `body` 或 `content` 或 `text`
- `tags`
- `type`

### JSONL

- 每行一个 JSON 对象。
- 空行跳过。

### CSV

- 第一行作为表头。
- 优先识别 `title/name`、`body/content/text`、`tags`、`type` 字段。
- 没有标题字段时使用文件名加行号。
- 没有正文字段时把整行转成可读文本。

## 不做

- 第一阶段不解析 PDF、Word、图片 OCR。
- 第一阶段不做 Dify 远端集成。
- 第一阶段不做复杂分块和向量化。
- 第一阶段不做后台长任务队列。

- 默认模式为待审核，导入后候选出现在“待审核”页面。
